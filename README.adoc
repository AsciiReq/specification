= AsciiReq - Requirements with AsciiDoc
:toc:


== Purpose

This project specifies a format based on
link:https://docs.asciidoctor.org/asciidoc/latest/[AsciiDoc]
to write requirements compatible for requirement management.

Requirement management tools are not part of this repository,
but are expected as tier tools.


== Example

AsciiReq syntax:

[source, asciidoc]
----
[#REQ-010, reftext="REQ-010", .req]
REQ-010:: _Requirement title_
+
--
Text defining the requirement body.

The requirement body may contain several paragraphs.

It may also use regular AsciiDoc formatting syntax
(such as lists, tables, admonitions, ...)
--
+
* *Version:* 1.0
* *Refers:*
** UPPER-REQ-100 - 1.2
*** Coverage justification.
----

Regular AsciiDoc rendering:

****

== Motivation

One major interest of defining a specification format
based upon a plain text technology
such as link:https://docs.asciidoctor.org/asciidoc/latest/[AsciiDoc]
is that it makes it compatible with source code management tools
like link:https://git-scm.com/[git].
Doing so, lots of aspects become easier:

* modification history,
* collaborative working,
* branches,
* versioning,
* ...

Furthermore,
link:https://mermaid.js.org/intro/[Mermaid] diagrams,
being a plain text technology as well,
integrate naturally with AsciiDoc,
which makes great sense when writing specifications.

Using link:https://docs.asciidoctor.org/asciidoc/latest/[AsciiDoc]
instead of link:https://daringfireball.net/projects/markdown/syntax[Markdown]
is motivated by the fact that AsciiDoc comes with a couple of native key features
which make it easier to write and maintain large technical documentations:

* automatic link:https://docs.asciidoctor.org/asciidoc/latest/toc/[table of content],
* automatic link:https://docs.asciidoctor.org/asciidoc/latest/sections/numbers/[section numbers]
* link:https://docs.asciidoctor.org/asciidoc/latest/directives/include/[includes]
  which make it possible to split a large document,
* better link:https://docs.asciidoctor.org/asciidoc/latest/tables/build-a-basic-table/[table] management in smaller lines,
* better link:https://docs.asciidoctor.org/asciidoc/latest/macros/xref/[cross-reference] support,
* ...

== Repository layout

Source `.adoc` files live in the `src/` directory.
The specification is split into one `.adoc` file per section,
included from `src/asciireq-specification.adoc`.

Only two `.adoc` files are published at the root of this repository:
`README.adoc` and `asciireq-specification.adoc`.
They are generated from `src/` with `npm run publish` (after `npm install`),
which resolves the AsciiDoc `include::` directives with
link:https://docs.asciidoctor.org/asciidoctor.js/latest/[asciidoctor.js],
so that the published files are self-contained
and render correctly on GitHub
(GitHub does not resolve AsciiDoc includes itself).
Do not edit the root files directly:
edit the sources in `src/`, then run `npm run publish`.
