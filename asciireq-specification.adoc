=== Purpose

This document specifies the AsciiReq format,
used to write requirements with AsciiDoc.

An AsciiReq document is a regular AsciiDoc document.
Requirements are written inside it, following the conventions defined below,
so that they can be identified, referenced and processed by tier tools.

The following example shows the format in action:

[source, asciidoc]
----
[.req]
REQ-010-v1.0::
Requirement title
+
--
Text defining the requirement body.

The requirement body may contain several paragraphs.

It may also use regular AsciiDoc formatting syntax
(such as lists, tables, admonitions, ...)
--
+
* Type: example
* Refers: UPPER-REQ-100
** Coverage justification.
----


=== Motivation

In the age of AI,
it is essential to constitute a clear specification format
to help AI agents work even better.
Clear specifications lead to better verifications,
and thus better quality.

One major interest of defining a specification format
based upon a plain text technology
such as link:https://docs.asciidoctor.org/asciidoc/latest/[AsciiDoc]
is that it makes it compatible with source code management tools
like link:https://git-scm.com/[git].
By the way, lots of aspects become easier:

* modification history,
* collaborative working, even with AI agents,
* branches,
* versioning,
* ...

Furthermore,
link:https://mermaid.js.org/intro/[Mermaid] diagrams,
being a plain text technology as well,
integrate naturally with AsciiDoc,
which makes great sens when writing specifications.

Using AsciiDoc
instead of link:https://daringfireball.net/projects/markdown/syntax/[Markdown]
is motivated by the fact that AsciiDoc comes with a couple of native key features
which make it easier to write and maintain large technical documentations:

* automatic link:https://docs.asciidoctor.org/asciidoc/latest/toc/[table of content],
* automatic link:https://docs.asciidoctor.org/asciidoc/latest/sections/numbers/[section numbers]
* link:https://docs.asciidoctor.org/asciidoc/latest/directives/include/[includes]
  which make it possible to split a large document,
* better link:https://docs.asciidoctor.org/asciidoc/latest/tables/build-a-basic-table/[table] management in smaller lines,
* better link:https://docs.asciidoctor.org/asciidoc/latest/macros/xref/[cross-reference] support,
* ...


== Actors

The following actors interact with AsciiReq specifications.

[#ASCIIREQ-WRITER, reftext="ASCIIREQ-WRITER", .req-actor]
ASCIIREQ-WRITER::
AsciiReq writer
+
--
Writes and maintains AsciiReq specifications.

May be a human or a tool.
--

[#ASCIIREQ-READER, reftext="ASCIIREQ-READER", .req-actor]
ASCIIREQ-READER::
AsciiReq reader
+
--
Reads AsciiReq specifications.

May be a human or a tool.
--

[#ASCIIDOC-RENDERER, reftext="ASCIIDOC-RENDERER", .req-actor]
ASCIIDOC-RENDERER::
AsciiDoc renderer
+
--
Reads AsciiDoc documents (possibly containing AsciiReq content)
and makes a presentation of it for humans.

Basically a tool.
--

==== General AsciiDoc requirement syntax

The AsciiReq format must enable
the processing of requirement documents
in a fast and deterministic way.

[#ASCIIREQ-REQ-010, reftext="ASCIIREQ-REQ-010", .req]
ASCIIREQ-REQ-010::
AsciiReq item
+
--
Inside an AsciiDoc document,
an AsciiReq item is defined
as a link:https://docs.asciidoctor.org/asciidoc/latest/lists/description/[description list] item
with an link:https://docs.asciidoctor.org/asciidoc/latest/attributes/role/[AsciiDoc role]
assigned to it being only one of :

`.req-ref`:: The `.req-ref` AsciiDoc role defines a foreign document reference.
`.req-actor`:: The `.req-actor` AsciiDoc role defines a formal AsciiReq actor.
`.req-data`:: The `.req-data` AsciiDoc role defines a formal AsciiReq data.
`.req`:: The `.req` AsciiDoc role defines an AsciiReq requirement.
--
+
* Version: 1.0.0
* Type: format


The following requirement ensures
that the whole content of an <<ASCIIREQ-ITEM>>
remains _AsciiDoc-ly_ attached to it.

[#ASCIIREQ-REQ-015, reftext="ASCIIREQ-REQ-015", .req]
ASCIIREQ-REQ-015::
AsciiReq item content
+
--
The _description_ (as of the link:https://docs.asciidoctor.org/asciidoc/latest/lists/description/#anatomy[anatomy of a description list item])
of an <<ASCIIREQ-ITEM>>
must be link:https://docs.asciidoctor.org/asciidoc/latest/lists/continuation/[compound].

link:https://docs.asciidoctor.org/asciidoc/latest/lists/continuation/#list-continuation[List continuations] (i.e. `+` lines)
must be used to ensure the continuation of the _description_.
--
+
* Version: 1.0.0
* Type: format


==== Requirement identifier

Requirement management commonly requires
that requirements be identified
with unique identifiers.

[#ASCIIREQ-REQ-020, reftext="ASCIIREQ-REQ-020", .req]
ASCIIREQ-REQ-020::
Requirement identifier
+
--
The _term_ (as of the link:https://docs.asciidoctor.org/asciidoc/latest/lists/description/#anatomy[anatomy] of a description list item)
of an <<ASCIIREQ-REQUIREMENT>>
constitutes the identifier of the requirement.
--
+
* Version: 1.0.0
* Type: format


==== Requirement title

It is usually practical to define requirement titles,
i.e. a short phrase summarizing the purpose off the requirement.
This is especially useful
when requirements are listed in tables,
in order to quickly understand
what the requirement talks about.

[#ASCIIREQ-REQ-030, reftext="ASCIIREQ-REQ-030", .req]
ASCIIREQ-REQ-030::
Requirement title
+
--
A requirement title may optionally be defined
as a first non link:https://docs.asciidoctor.org/asciidoc/latest/blocks/open-blocks/[open block] paragraph
in the <<REQUIREMENT-CONTENT>>.
--
+
* Version: 1.0.0
* Type: format

The <<ASCIIREQ-REQ-030>> requirement labels "first (...) paragraph"
for compliance purpose with AsciiDoc syntax definitions,
but the requirement title shall generally be a single line in practice.

[NOTE]
.One line heading style
====
Considering that requirement titles usually consist of a single line,
we may consider a good option to present the requirement title on the same text line as the <<ASCIIREQ-IDENTIFIER>>.
Doing so enables `grep` commands to retrieve corresponding requirement identifiers and titles
in a row.

Let's call it the _one line heading_ style.

==== Requirement body

The requirement body then gives the full text of the requirement.

[#ASCIIREQ-REQ-040, reftext="ASCIIREQ-REQ-040", .req]
ASCIIREQ-REQ-040::
Requirement body
+
--
The requirement body is given
as a single link:https://docs.asciidoctor.org/asciidoc/latest/blocks/open-blocks/[open block]
in the <<REQUIREMENT-CONTENT>>.
--
+
* Version: 1.0.0
* Type: format

Defining the requirement body as an open block makes it possible to
write it freely with several paragraphs,
and use any AsciiDoc formatting (lists, tables, admonitions, ...).


==== Requirement attributes

Requirement management commonly requires the usage of additional attributes
attached with the requirements.

[#ASCIIREQ-REQ-050, reftext="ASCIIREQ-REQ-050", .req]
ASCIIREQ-REQ-050::
Requirement attributes
+
--
Requirement attributes may be defined
in a unique AsciiDoc link:https://docs.asciidoctor.org/asciidoc/latest/lists/unordered/[unordered list]
of `name: value` pairs,
placed after the requirement body (as of <<Requirement body>>).
--
+
* Version: 1.0.0
* Type: format
