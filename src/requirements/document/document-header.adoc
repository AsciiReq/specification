[#asciireq-document-header]
= Document header

In order to make it clear
that an AsciiDoc document contains AsciiReq content,
and which version of the specification is used,
a declaration shall be made
in the <<ASCIIDOC>> link:https://docs.asciidoctor.org/asciidoc/latest/document/header/[document header].

[NOTE]
.AsciiDoc custom attributes
====
The definition of link:https://docs.asciidoctor.org/asciidoc/latest/attributes/custom-attributes/[custom attributes]
is natively allowed by the AsciiDoc format,
which makes the definition of <<ASCIIREQ>> document attributes possible.
====

The single <<ASCIIDOC>> custom attribute defined for <<ASCIIREQ>>
gives the AsciiReq version used to write the current document.

[#ASCIIREQ-HEADER-0200, reftext="ASCIIREQ-HEADER-0200", .req]
ASCIIREQ-HEADER-0200:: _AsciiReq version declaration_
+
--
When writing an <<ASCIIREQ-DOCUMENT>>,
the `:asciireq-version:`
<<ASCIIDOC>> link:https://docs.asciidoctor.org/asciidoc/latest/attributes/document-attributes/[document attribute]
MUST be declared
in the <<ASCIIDOC>> link:https://docs.asciidoctor.org/asciidoc/latest/document/header/[document header].

This document attribute value
MUST be a URL
giving the AsciiReq version (as of <<ASCIIREQ-HEADER-0220>>)
used to write the <<ASCIIREQ-DOCUMENT>>.
--
+
* *Version:* 0.1
* *Actors:*
** <<ASCIIREQ-WRITER>>

Let's formally identify the `:asciireq-version:` document attribute as <<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>>.

The usage of the <<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>> is required on purpose,
so that an <<ASCIIREQ-READER>>
can figure out which version of AsciiReq it is working with.

[#ASCIIREQ-HEADER-0210, reftext="ASCIIREQ-HEADER-0210", .req]
ASCIIREQ-HEADER-0210:: _AsciiReq version processing_
+
--
An <<ASCIIREQ-READER>>,
when reading an <<ASCIIDOC>> document
containing an <<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>>,
MUST process the document as an <<ASCIIREQ-DOCUMENT>>,
according to the AsciiReq version specified as of <<ASCIIREQ-HEADER-0220>>.

If the <<ASCIIREQ-READER>> does not handle the AsciiReq version specified,
it SHOULD display a warning message.
--
+
* *Version:* 0.1
* *Actors:*
** <<ASCIIREQ-READER>>

If the reader does not handle the AsciiReq version specified,
or no AsciiReq version is specified,
it is its own responsibility to decide the behavior after,
either:

* stop processing;
* consider the latest AsciiReq version it knows by default;
* try to guess the AsciiReq version from the document content;
* ...

The URLs specified with <<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>>s
are browsable URLs,
in order to help humans
easily find and read through the referenced specification.

[#ASCIIREQ-HEADER-0220, reftext="ASCIIREQ-HEADER-0220", .req]
ASCIIREQ-HEADER-0220:: _AsciiReq versioned URLs_
+
--
The table below gives the known values
as of this version of the <<ASCIIREQ>> specification,
for <<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>>s:

[cols="1,5"]
|===
|<<ASCIIREQ>> specification version |<<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>> value

|0.1
|https://github.com/AsciiReq/specification/blob/0.1/asciireq-specification.adoc
|===
--
+
* *Version:* 0.1
* *Actors:*
** <<ASCIIREQ-WRITER>>
** <<ASCIIREQ-READER>>

The URLs are currently defined with GitHub URLs,
but the project could possibly be hosted somewhere else later.
That's the reason why an <<ASCIIREQ-READER>> may fetch the URL if it does not know it yet.

[#ASCIIREQ-HEADER-0230, reftext="ASCIIREQ-HEADER-0230", .req]
ASCIIREQ-HEADER-0230:: _AsciiReq URL fetching_
+
--
If an <<ASCIIREQ-READER>> does not know the URL given by the <<ASCIIREQ-VERSION-DOCUMENT-ATTRIBUTE>>,
it MAY fetch the URL given
and check for the `:revnumber:` in the document header.
--
+
* *Version:* 0.1
* *Actors:*
** <<ASCIIREQ-READER>>

It is an option, but not a recommendation, for security reasons.

As of <<SEMVER>>, _PATCH_ versions won't break the compatibility.
That's the reason why there is no need to give them with AsciiReq versioned URLs.

Other document headings are specified
later in this specification.
See:

* <<ASCIIREQ-DOCUMENT-VERSION>>
